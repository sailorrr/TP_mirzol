# Спецификация прецедентов (Use Case Specification)

**Проект:** Кроссплатформенное приложение криптографических методов и алгоритмов (Qt6 / C++)
**Версия:** 1.0
**Дата:** 2026-09-26

---

## 1. Актеры (Actors)

| Актер | Тип | Описание |
| :--- | :--- | :--- |
| **Пользователь (User)** | Основной | Студент или клиент системы, использующий математические алгоритмы и криптомодули. |
| **Администратор (Admin)** | Основной | Пользователь с повышенными правами (заложено в архитектуру). |
| **Сервер (Server)** | Второстепенный | Внешняя система (эхо-сервер-заглушка), обрабатывающая запросы и проверяющая авторизацию. |

---

## 2. Диаграмма прецедентов (Структурное описание)

Визуально диаграмма разделена на три системных блока:

### Блок А: Безопасность и Доступ
* **Прецедент:** Авторизация (Вход в систему)
* **Прецедент:** Отправка запроса на Сервер
* **Связи:**
  * `Авторизация` включает (`<<include>>`) `Отправка запроса на Сервер`.
  * `Отправка запроса` включает (`<<include>>`) `Валидация формата данных (parse)`.

### Блок Б: Криптография и Алгоритмы (Бизнес-логика)
* **Прецедент:** Использовать Шифр Виженера
  * `<<include>>` → Зашифровать текст по ключу
  * `<<include>>` → Расшифровать текст по ключу
  * `<<extend>>` → Ограничение ввода (валидация латиницы)
* **Прецедент:** Использовать md5-хэш
  * `<<include>>` → Сгенерировать хэш
  * `<<extend>>` → Сравнить с эталоном
* **Прецедент:** Использовать Метод секущих
  * `<<include>>` → Решить уравнение f(x) = 0
* **Прецедент:** Использовать Проверку цикла графа
  * `<<include>>` → Проверить последовательность вершин

### Блок В: Дополнительные функции
* **Прецедент:** Просмотр истории операций
* **Прецедент:** Очистка истории операций

## 3. Подробное описание ключевых прецедентов

### Прецедент 1: Авторизация пользователя (UC-01)

* **Идентификатор:** UC-01
* **Главный актер:** Пользователь
* **Второстепенный актер:** Сервер
* **Предусловие:** Приложение запущено, активно окно `LoginWindow`.
* **Основной поток (Basic Flow):**
  1. Пользователь вводит логин и пароль.
  2. Пользователь нажимает кнопку «Войти».
  3. Система выполняет локальную проверку на пустые поля.
  4. Система формирует строку протокола: `auth&login&password`.
  5. Система отправляет запрос в `ServerStub`.
  6. Сервер возвращает `auth&ok`.
  7. Система сохраняет пользователя в Singleton `Client`.
  8. Открывается главное меню `UserWindow`.
* **Альтернативный поток (Ошибка):**
  * 3а. Поля пустые → предупреждение, отправка блокируется.
  * 6а. Сервер возвращает `auth&fail` → сообщение «Неверные данные».

---

### Прецедент 2: Использование Шифра Виженера (UC-02)

* **Идентификатор:** UC-02
* **Главный актер:** Пользователь
* **Предусловие:** Пользователь авторизован, открыл раздел «Шифр Виженера».
* **Основной поток (Шифрование):**
  1. Пользователь вводит исходный текст на латинице.
  2. Пользователь вводит ключевое слово.
  3. Пользователь нажимает «Зашифровать».
  4. Система вызывает `VigenereCipher::encrypt`.
  5. Результат (шифртекст) отображается в поле вывода.
* **Расширение (Валидация):**
  * При вводе кириллицы или цифр система выводит ошибку.
* **Основной поток (Расшифровка):**
  1-3. Аналогично, но кнопка «Расшифровать».
  4. Система вызывает `VigenereCipher::decrypt`.

---

### Прецедент 3: Генерация и проверка md5 (UC-03)

* **Идентификатор:** UC-03
* **Главный актер:** Пользователь
* **Предусловие:** Пользователь открыл криптомодуль md5.
* **Основной поток:**
  1. Пользователь вводит текст.
  2. Пользователь нажимает «Хэшировать».
  3. Система генерирует md5-хэш (`MD5::hash`).
  4. Хэш отображается в поле.
  5. Пользователь может скопировать хэш в буфер обмена.
  6. Пользователь вставляет эталонный хэш в поле сравнения.
  7. Пользователь нажимает «Проверить соответствие».
  8. Система сравнивает и показывает «✅ СОВПАДЕНИЕ!» или «❌ НЕ СОВПАДАЕТ».

---

### Прецедент 4: Метод секущих (UC-04)

* **Идентификатор:** UC-04
* **Главный актер:** Пользователь
* **Предусловие:** Пользователь открыл модуль «Метод секущих».
* **Основной поток:**
  1. Пользователь вводит x₀, x₁ (начальные приближения).
  2. Пользователь вводит ε (точность).
  3. Пользователь нажимает «Найти корень».
  4. Система вызывает `SecantMethod::solve`.
  5. Результат (корень, f(x)) отображается.

---

### Прецедент 5: Проверка цикла графа (UC-05)

* **Идентификатор:** UC-05
* **Главный актер:** Пользователь
* **Предусловие:** Пользователь открыл модуль «Проверка цикла».
* **Основной поток:**
  1. Пользователь задаёт матрицу смежности 5×5 (0/1).
  2. Пользователь вводит последовательность вершин (например, «1 3 4 2 1»).
  3. Пользователь нажимает «Проверить».
  4. Система вызывает `GraphCycle::isCycle`.
  5. Результат: «✅ ЦИКЛ!» или «❌ НЕ ЦИКЛ».

---

### Прецедент 6: История операций (UC-06)

* **Идентификатор:** UC-06
* **Главный актер:** Пользователь
* **Предусловие:** Пользователь авторизован.
* **Основной поток:**
  1. Пользователь нажимает «📊 История операций».
  2. Открывается `HistoryWindow`.
  3. Таблица `QTableWidget` отображает историю (из `Client::getHistory`).
  4. Пользователь может обновить («🔄») или очистить («🗑») историю.
